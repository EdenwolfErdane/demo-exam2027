Задание 5. Формирование статистики по заказам и разработка руководства пользователя

Для подведения итогов работы предприятия заказчику требуется дополнить разработанную информационную систему окном (отчетом) просмотра общей статистики по заказам для ролей Администратора и Менеджера, а также подготовить краткую инструкцию пользователя.

Разработка окна (отчета) «Статистика заказов»

В интерфейсах Менеджера и Администратора необходимо добавить кнопку «Статистика» (или «Отчет по заказам»), при нажатии на которую открывается новое окно (форма или отчет).

На форме должна отображаться таблица (список) всех заказов из базы данных (номер/код заказа, дата заказа, ФИО клиента, итоговая сумма заказа), а также 3 общих статистических показателя по всем заказам:

  • общее количество заказов (заявок) в базе данных;
  • общая сумма выручки (суммарная стоимость всех заказов в рублях);
  • средняя (или максимальная) стоимость заказа в рублях.

Разработка эксплуатационной документации (Руководство пользователя)

Создать текстовый документ Руководство_пользователя.docx (или .pdf), содержащий краткую инструкцию по работе с разработанной системой (объемом 1–2 страницы):

  • краткое назначение программы и описание порядка входа в систему (авторизации);
  • описание основных возможностей программы со скриншотами разработанного интерфейса (не менее 3 скриншотов: например, экран каталога, экран работы с заказами, экран статистики).

Сохранение результатов

Все практические результаты выполнения Задания 5 (обновленный исходный код приложения, файл конфигурации .dt для платформы «1С» или скрипт БД, а также файл Руководство_пользователя.docx/.pdf) необходимо загрузить в предоставленный репозиторий системы контроля версий.

Шаг 4. Код окна: таблица и три показателя

Весь код окна помещается в один метод LoadStats, который вызывается из конструктора. Это дословно файл StatisticsForm.cs из архива:

public partial class StatisticsForm : Form
{
    public StatisticsForm()
    {
        InitializeComponent();
        LoadStats();
    }

    void LoadStats()
    {
        // Все заказы базы с итоговой суммой каждого (сумма строк заказа).
        // LEFT JOIN нужен, чтобы заказ без позиций тоже попал в список (с суммой 0).
        var t = Db.Table(@"SELECT o.Код_заказа AS Номер, o.Дата_заказа AS Дата,
                                  u.Фамилия + ' ' + u.Имя AS Клиент,
                                  ISNULL(SUM(oi.Количество * oi.Цена_за_единицу), 0) AS Сумма
                           FROM Заказы o
                           JOIN Пользователи u ON u.Код_пользователя = o.Код_пользователя
                           LEFT JOIN Строки_заказов oi ON oi.Код_заказа = o.Код_заказа
                           GROUP BY o.Код_заказа, o.Дата_заказа, u.Фамилия, u.Имя
                           ORDER BY o.Код_заказа");
        gridOrders.DataSource = t;

        // Три общих показателя считаем по уже полученной таблице.
        decimal revenue = 0;
        foreach (DataRow r in t.Rows) revenue += (decimal)r["Сумма"];
        lblCount.Text = "Всего заказов: " + t.Rows.Count;
        lblRevenue.Text = "Общая выручка: " + revenue.ToString("N2") + " ₽";
        lblAverage.Text = "Средний чек: " + (t.Rows.Count == 0 ? 0m : revenue / t.Rows.Count).ToString("N2") + " ₽";
    }

    private void btnBack_Click(object sender, EventArgs e) { Close(); }
}

Класс Db (файл Db.cs) уже умеет возвращать таблицу по тексту запроса: Db.Table("SELECT ..."). Строку подключения он берёт из App.config — та самая, что указывает на Чудо_Обувь.mdf.

Запустите программу (F5) → войдите менеджером papetrov → кнопка «Статистика» → окно должно показать: 10 заказов, выручка 341 770,00 ₽, средний чек 34 177,00 ₽. Сверьте пару строк таблицы с заказами в разделе «Заказы».

Подробное объяснение

Выше — что нажимать и что писать. Здесь — почему решение устроено именно так: как формируется таблица заказов, откуда берутся три показателя и как работает разграничение прав. Эти вопросы обычно задают на защите.

Почему запрос такой: GROUP BY и LEFT JOIN

Главная ловушка задания: итоговой суммы заказа в базе нет. Откройте таблицу Заказы — там номер, дата, код клиента, но никакого поля «Сумма». Сумма складывается из позиций заказа: в Строки_заказов лежит Количество × Цена_за_единицу по каждой позиции. Поэтому окно нельзя заполнить простым SELECT * FROM Заказы — сумму для каждого заказа нужно посчитать и свернуть.

Фрагмент запросаЧто делает
JOIN Пользователи u ON u.Код_пользователя = o.Код_пользователяв Заказах хранится только код клиента — ФИО берём из Пользователей и склеиваем: Фамилия + ' ' + Имя
LEFT JOIN Строки_заказов oi ON oi.Код_заказа = o.Код_заказаприсоединяет позиции заказа. LEFT, а не обычный JOIN: заказ, у которого удалили последнюю позицию, не должен исчезнуть из списка «всех заказов»
ISNULL(SUM(...), 0)у заказа без позиций SUM вернёт NULL — ISNULL превращает его в 0, и сумма в таблице не пустая
GROUP BY o.Код_заказа, o.Дата_заказа, u.Фамилия, u.Имясворачивает все позиции одного заказа в одну строку с итогом SUM; в SELECT при этом можно указывать только перечисленные поля и агрегаты
ORDER BY o.Код_заказазаказы идут по возрастанию номера — так же, как в разделе «Заказы»
AS Номер, AS Дата, AS Клиент, AS Суммаалиасы становятся заголовками колонок таблицы — никаких «Код_заказа1» в интерфейсе
Две типичные ошибки. Первая — обычный JOIN вместо LEFT JOIN: заказ без позиций пропадает из списка, и формально «таблица всех заказов» показана неполно. Вторая — забыть GROUP BY: тогда заказ размножится по строке на каждую позицию, а «Сумма» будет суммой одной позиции, а не заказа.

Откуда берутся три показателя

Показатели считаются по таблице t, которую вы уже вывели, — второй раз базу дёргать не нужно:

  • Всего заказов = количество строк таблицы (t.Rows.Count) — таблица содержит все заказы базы, поэтому число строк и есть «общее количество заказов»;
  • Общая выручка = сумма по колонке «Сумма» — то есть суммарная стоимость всех заказов. Не «сумма цен товаров из каталога» — именно сумма заказов!
  • Средний чек = выручка ÷ количество заказов (revenue / t.Rows.Count). Тернарник t.Rows.Count == 0 ? 0m : ... защищает от деления на ноль, если заказов в базе нет.

Почему decimal, а не double: это деньги. double даёт хвосты вроде 34176,999999, decimal считает точно. Формат N2 даёт привычные «341 770,00». И в задании допускается максимальная стоимость вместо средней — если делаете её, возьмите MAX по той же колонке.

Сверить всё с базой можно одним SQL-запросом. Откройте окно запроса: в обозревателе решения двойной щелчок по Чудо_Обувь.mdf → в «Серверном обозревателе» правой кнопкой по подключению → Создать запрос → вставьте:

SELECT COUNT(*) AS Всего_заказов,
       ISNULL(SUM(oi.Количество * oi.Цена_за_единицу), 0) AS Общая_выручка,
       ISNULL(SUM(oi.Количество * oi.Цена_за_единицу), 0)
           / NULLIF((SELECT COUNT(*) FROM Заказы), 0) AS Средний_чек
FROM Заказы o LEFT JOIN Строки_заказов oi ON oi.Код_заказа = o.Код_заказа;

Те же запросы (по заказам и по показателям) уже лежат в Database/Проверка.sql — раздел 5.

Для учебной базы должно получиться: 10 заказов, выручка 341 770,00 ₽, средний чек 34 177,00 ₽. Числа в окне программы и в запросе совпали — расчёты верные. Проверяйте после каждого добавления/удаления заказа: цифры должны меняться.

Кто видит кнопку «Статистика»

Задание требует окно «для ролей Администратора и Менеджера». В программе роль вошедшего лежит в Session.Role, а «персонал» описан одним свойством (файл Session.cs):

public static bool IsAdmin { get { return Role.StartsWith("Админ"); } }
public static bool IsStaff { get { return IsAdmin || Role.StartsWith("Менед"); } }
Кто вошёлКнопка «Статистика»
Гость («Без входа»)нет
Пользователь (например, asidorova)нет
Менеджер (papetrov)да
Администратор (isivanov)да

Отдельный случай — режим pick: когда каталог открыт из окна «Заказы» для добавления позиции, кнопки «Заказы» и «Статистика» прячутся, а «Выйти» становится «Назад». Окно статистики из окна выбора товара не нужно — иначе окна будут вкладываться друг в друга, и запутаться станет проще, чем разобраться.

Проверяйте кнопку реальными запусками под всеми ролями: менеджер и администратор — видят и открывают окно; гость и пользователь — кнопки нет. Кнопка, перекрытая соседним элементом, «идеально выглядит» в дизайнере и не нажимается на запуске.
